# PerfectWork 2 改善レポート

対象: `app_perfectwork`。2026年9月6日。

## 改修の方針

機能を探し回る構成から、ホームを起点に「メモ → タスク → 週間計画 → 集中 → 振り返り」がつながる構成へ変更しました。空の状態でも次の操作が分かるガイドと、実際のデータを作成するテンプレートを追加。見た目は余白のある明るいワークスペースへ刷新し、ダークテーマも選択できます。

## 追加した体験

- 今日の目標、予定・期限タスク、優先度からの提案、集中、習慣、プロジェクトを集めたホーム。
- タスクボード／リスト、検索、プロジェクト別・期限超過の絞り込み、予定日、見積時間、チェックリスト。
- 週間プランと未予定タスク一覧、日付指定でのタスク追加。
- メモのカード表示、本文・タグ検索、お気に入り、保管・復帰。
- プロジェクト詳細での関連タスク・ノート・リンク・作業時間・記録の確認。
- タスクにひも付く15・25・50・90分の集中タイマー。一時停止・再開と、振り返り記録・タスク完了。
- 習慣の登録、直近7日のチェック・修正、保管・復帰。
- 作業記録の編集と期間別の振り返り、選択期間だけの日報出力。
- プロジェクト立ち上げ、学習、仕事環境リセットのテンプレートと使い方ガイド。
- アプリ内のタスク・メモ・プロジェクトも探せるコマンドパレット。

## 確認して修正した問題

| 問題                                                                    | 修正                                                                             |
| ----------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| 非同期保存後の `event.currentTarget` が無効になり、ダイアログが閉じない | フォーム参照を保存前に保持。メモ・タスク・プロジェクト・記録・自動化・設定で検証 |
| 作成フォームのプロジェクト状態・進捗が無視される                        | 作成時から反映し、範囲を検証                                                     |
| プロジェクトの色変更が保存されない                                      | 更新処理に色検証・保存を追加                                                     |
| プロジェクト編集で2件目以降の関連リンクが消える                         | 未編集のリンクを保持                                                             |
| UTC日付により日本時間の朝に今日の集計がずれる                           | 日付判定、集中集計、活動記録、自動化をローカル日付へ統一                         |
| 存在しない日付が受理される                                              | 日付文字列と実際の日付の一致を検証                                               |
| 連続記録が14日を超えない                                                | グラフの表示期間と継続日数の計算を分離                                           |
| 完了済みタスクへの再更新で完了日が変わる                                | 完了日時を保持。保管・復帰時も維持                                               |
| 同じメモから重複してタスクを作成できる                                  | 変換先を記録し、並行変換も1件に制限                                              |
| メモからタスクへの変換でURLを失う                                       | 本文とURLの両方を引き継ぐ                                                        |
| 遅い検索応答が新しい検索結果を上書きする                                | 要求の世代を確認し、古い応答を破棄                                               |
| 検索画面でファイルを開くと検索内容がリセットされる                      | 画面の再描画が必要な更新だけ再描画                                               |
| CSPにより既存の進捗・グラフ用スタイル属性が描画されない                 | スタイル属性の方針を明示。スクリプトと外部リソースの制限は保持                   |
| 検索フォルダの重なりで二重計上・偽の重複候補が発生する                  | 同一ディレクトリを一度だけ走査。検索ルート自体のリンクも追跡しない               |
| 検索の失敗時に索引作成中のまま残る                                      | 失敗状態を記録                                                                   |
| 「起動時」自動化が定期チェックでも動く                                  | 起動時と日次の条件を分離                                                         |
| 長い自動処理の重複起動・失敗履歴の増え続け                              | 同時実行を抑止し、同日の失敗を繰り返さず、履歴件数を制限                         |
| デモと通常版でセッションCookieが衝突する                                | 起動ポートごとのCookie名に変更                                                   |
| 二重起動で同じデータを持つ複数の書き込みプロセスができる                | 起動済みワークスペースを再利用                                                   |
| 根拠の分かりにくい「PC環境スコア」                                      | ファイル診断へ名称変更し、実際のスキャン範囲・候補を表示                         |

## 検証

- `npm.cmd test`: 53件。既存のファイル整理・Undo検証とグローバル起動キー設定を含む。
- `npm.cmd run test:ui`: 21項目。実際のChromiumで全11画面、フォーム保存・編集、テンプレート、集中・習慣・自動化、検索競合、画面復帰を確認。
- 1440pxのホーム、ライト／ダーク表示、390pxのホームをスクリーンショットで確認。390pxでは全11画面のページ全体の横溢れも検証。
- `npm.cmd audit --omit=dev`: 報告された脆弱性0件。
- `npm.cmd run test:postgres`: 実際のPostgreSQL上の分離スキーマで保存・再接続・JSONミラー・競合防止を確認。終了時にテストスキーマを削除。
- 検証には独立した一時ワークスペースを使用。ユーザーの記録にテストデータを追加しない。

## PostgreSQL移行

入力情報の正本をPostgreSQLへ移しました。状態更新、直近100版のリビジョン、タスク等の構造化索引を同じトランザクションで確定し、その後に`workspace.json`を復旧用ミラーとして更新します。既存JSONは初回接続時に自動インポートし、移行前コピーを保存します。DB接続に失敗した場合はJSONへ暗黙に切り替えないため、二つの正本が生まれません。

これは検証した範囲の結果です。未知の不具合がないことや、あらゆる環境での動作を保証するものではありません。実データが大きい場合の長時間負荷、OS通知、外部カレンダー同期、チーム共有、OCR、バックアップ取り込み画面は今回の対象に含めていません。
