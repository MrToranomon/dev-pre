# TigerGate

2026年9月9日・2.6.0: 集中タイマーは1〜180分を1分単位で入力できます。15/25/50/90分のプリセットも利用できます。ファイル診断を開くと、選択対象があるドライブ全体の使用率（同じドライブは1回）と、選択範囲内の容量上位10件を自動表示します。「表示フォルダを選択」からチェックやWindows標準の参照画面で対象を変更できます。検索対象とは独立して保存します。

容量ランキングは直下のサブフォルダと直下ファイルの合計、または選択フォルダ別に切り替えられます。割合の分母は各ドライブの総容量です。フォルダは論理サイズであり、クラウド・圧縮・ハードリンク等で物理使用量と異なる場合があります。リンク先は追跡せず、最大20万ファイル・2万ディレクトリ・約20秒で一部集計として表示します。前回結果はローカルにキャッシュし、5分以内は再利用、「更新」で再集計できます。重複等の詳細診断は従来の除外・件数制限で別途実行します。

実装参照: [Node.jsのファイルシステム容量取得](https://nodejs.org/api/fs.html#class-fsstatfs)、[Electronのフォルダ選択ダイアログ](https://www.electronjs.org/docs/latest/api/dialog#dialogshowopendialogbrowserwindow-options)。

TigerGateは、仕事・知識・ファイル・進捗を一つの流れにつなぐ、Windows向けのローカルファースト作業アプリです。データと検索索引はPC内に保存され、クラウドアカウントや外部サーバーを必要としません。

2026年9月9日: TigerGate（旧PerfectWork）2.5.0。虎のアイコン、琥珀色のアクセント、一括タスク追加、空き時間からのタスク候補を追加しました。宣伝的な文言と装飾バナーを減らし、保存中の全画面ローディングを廃止しています。AIチャットは未実装です。

## 起動

このPCでは `Win+Insert`、デスクトップまたはスタートメニューの「TigerGate」から専用ウィンドウが開きます。再実行すると既存ウィンドウを手前に表示します。実行ファイルは `dist\releases\2.6.0\TigerGate-win32-x64\TigerGate.exe` です。

×で閉じると通知領域に待機します。完全に終了するには通知領域のメニューから「終了」、またはウィンドウ内で `Ctrl+Q` を使います。ウィンドウの大きさ・位置は次回起動時に復元されます。Windows版には実行環境を同梱しているため、起動に別途Node.jsは必要ありません。PostgreSQL利用時はデータベースの起動が必要です。

開発用にソースから起動する場合はNode.js 22.13以降を使います。

```powershell
npm.cmd install
npm.cmd run work
```

別のPCへ導入する場合は、PostgreSQLを起動してから初回だけ `npm.cmd run setup:postgres` を実行します。専用DB・専用ロール・暗号化済み接続設定を作成します。

`launch-perfectwork.vbs` をダブルクリックしても起動できます。サンプルデータだけで試す場合は、実際のDocumentsやDownloadsに触れないデモを使用してください。

Windows版の作成は `npm.cmd run build:desktop`、ショートカットとホットキーの設定は `npm.cmd run setup:desktop` です。ブラウザ版が必要な場合は `npm.cmd run work:browser` を使用できます。再ビルド前にはアプリを終了し、既存の `dist\releases\2.6.0\TigerGate-win32-x64` をバックアップしてください（既存の配布フォルダは自動上書きしません）。

ホームとタスク画面では入力欄からEnterでタスクを追加できます。ホームで追加したタスクは今日の予定になります。`Ctrl+Shift+N` で詳細入力、フォーム内の `Ctrl+Enter` で保存できます。画面ごとの絞り込み・スクロール位置と直接入力欄の下書きは、ウィンドウを使用している間保持します。画面移動は履歴にも記録します。

Windowsのどの画面からでも起動するグローバルキーは、初回に次を実行すると有効になります。初期値は `Win+Insert` で、以後はTigerGateの設定画面から変更・無効化できます。常駐ランチャーはWindowsログイン時に自動起動します。

```powershell
npm.cmd run setup:hotkey
```

```powershell
npm.cmd run work:demo
```

このPCの通常起動では、TigerGateの入力データをPostgreSQLへ正本として保存します。`workspace.json`はDB確定後に自動更新する復旧用ミラー、`search-index.json`は再生成可能なファイル検索キャッシュです。詳しい構成は [PostgreSQL構成](docs/postgresql.md) を参照してください。

このPCではPostgreSQL 18の`perfectwork`データベースと、最小権限の`perfectwork_app`ロールを使用します。認証情報はWindows DPAPIで暗号化し、現在のWindowsユーザーだけが読める `%LOCALAPPDATA%\PerfectWork` に保存します。ソースコードやワークスペースJSONには書き込みません。

A5:SQL Mk-2からDBを確認・操作する場合は、Microsoft Store版をインストール後に `npm.cmd run setup:a5` を一度実行します。「PerfectWork」接続と、タスク等を読みやすく表示する参照ビューが利用できます。

起動済みなら同じワークスペースを開きます。複数のサーバーが同じデータを上書きすることを防ぎます。旧版からの更新時は旧サーバーを終了してから起動してください。既存データを引き継ぎ、サンプルデータは追加しません。

旧PerfectWorkのデータフォルダ・DB名・内部識別子は互換性のため維持しています。既存データの移動や初期化は行いません。

「一括追加」では改行区切りや箇条書きを最大50件のタスクに変換し、保存前に確認できます。「空き時間から選ぶ」は見積時間を使うローカル処理で、AI APIや外部送信は使いません。ファイル診断は同じドライブの空き容量を繰り返さず、確認したファイルの論理サイズをフォルダ別に表示します。入れ子の登録範囲は二重計上しません。

## 最初の3分

1. ホームの「今日の目標を決める」で、一番進めたいことを一文にします。
2. 「やることを追加する」で小さなタスクを作り、取り組む予定日を指定します。迷ったら「はじめ方・テンプレート」からプロジェクトと5つのタスクを用意できます。
3. タスクの「集中」から15・25・50・90分を選択。一時停止・再開でき、終わったら成果と一緒に記録します。

タスクの**予定日**は「いつ取り組むか」、**期限**は「いつまでに終えるか」です。週間プランには予定日で表示し、予定日がないタスクは期限の日に表示します。

## できること

- **新しいホーム** — 今日の目標、予定・期限タスク、集中、習慣、プロジェクトを集約。見積時間・期限・優先度で選ぶ15/30/60/90分の作業候補付き
- **全文検索** — ファイル名に加え、PDF、Word（`.docx`）、Markdown、テキスト、CSV、JSON、HTML、主要なソースコードの内容を横断検索
- **メモ・アイデア** — カード表示、タイトル・本文・タグ検索、お気に入り、保管・復帰。タスクへの変換ではURLも保持
- **タスクボード** — 未着手・進行中・完了のボードとリスト、検索・プロジェクト・期限超過フィルター、予定日、見積時間、チェックリスト、保管・復帰
- **週間プラン** — 前後の週へ移動、日別タスクと見積時間、予定未設定のタスク一覧、日付指定で追加
- **習慣トラッカー** — 習慣を登録し、直近7日をチェック・修正。保管しても記録を維持
- **実用テンプレート** — プロジェクトの立ち上げ、学習、仕事環境のリセット。内容を確認してプロジェクトと実際のタスクを一括作成
- **プロジェクト・ポータル** — ゴール、期限、進捗、関連フォルダ、タスクを集約。登録フォルダのGitブランチ、未コミット変更、最新コミットも確認
- **プロジェクト詳細** — 関連タスク、ノート、リンク、作業時間、最近の記録を一つの画面で確認し、そのプロジェクトにタスクを追加
- **集中セッション** — タスクと連動するカウントダウン、一時停止・再開、時間到達のお知らせ。終了時に成果を記録し、タスクも完了可能
- **振り返り** — 記録の追加・編集、7日・30日・全期間の切替、14日間のリズム、連続記録、選択期間のMarkdown日報出力
- **安全な自動化** — デイリーノート、インボックス・ダイジェスト、プロジェクト一覧、全データバックアップを手動・起動時・日次で実行
- **ファイル診断** — 対象フォルダの容量、巨大・古いファイル、SHA-256で一致する重複候補を読み取り専用で確認。スキャン範囲と上限を明示
- **コマンドパレット** — `Ctrl+K` / `⌘K` から全画面と操作に移動。タスク・メモ・プロジェクト・ファイルの名前を横断検索
- **表示と操作** — ライト／ダークテーマ、4種のアクセント、スマートフォン幅対応、キーボード操作、再読み込み時の画面復帰
- **Orbit連携** — 既存のDownloads整理・ルール管理アプリをTigerGateから起動
- **データポータビリティ** — 設定画面からTigerGateの全データをJSONで書き出し
- **PostgreSQL + JSON保護** — 構造化データはトランザクションで保存し、直近100版の履歴と検索用エンティティを保持。復旧用JSONミラーとPostgreSQLバックアップも作成
- **グローバル起動キー** — 初期値`Win+Insert`。好きなキーへ変更でき、Windowsログイン時からバックグラウンドで待機

## 安全性とプライバシー

TigerGateのHTTPサーバーは `127.0.0.1` だけで待ち受け、起動ごとのランダムトークン、Host/Origin検証、厳格なContent Security Policyを使います。認証情報やファイル内容を外部へ送信する処理はありません。

全文検索は設定したフォルダだけを対象とし、シンボリックリンクやジャンクションを追跡しません。`node_modules`、`.git`、ビルド出力なども除外します。初期値ではDocuments、Desktop、Downloadsが対象です。検索索引には抽出したテキストが含まれるため、PCを共同利用する場合はWindowsアカウントを分けてください。

PC診断は候補を表示するだけで、ファイルを削除しません。重複判定はファイルサイズとSHA-256の両方を使い、巨大ファイルはストリームで処理します。

自動化は設定した保存先の内側にだけ新規ファイルを作成し、既存ファイルを上書きしません。手動実行では内容をプレビューしてから確定します。自動化で作成後に編集していないファイルはUndoでき、変更済みファイルは保護のため残します。自動実行はアプリが起動している間だけ動作し、初期状態では無効です。

## 現在の制約

- 古い `.doc` は内容抽出せず、ファイル名だけを検索します。Word内容検索は `.docx` が対象です。
- スキャン上限と内容抽出の最大サイズは設定画面で調整できます。巨大な環境では対象フォルダを絞ると高速です。
- Git診断にはGitコマンドが必要です。Gitリポジトリでないフォルダも通常のプロジェクトとして利用できます。
- 自動化の時刻指定やOSログイン時の常駐実行はまだ行いません。起動中に1日1回の実行を確認します。
- ファイル内容のプレビュー表示、OCR、メール・カレンダー連携は今後の拡張ポイントです。
- 週間プランはアプリ内のタスク予定です。Google/Outlookカレンダーとの同期やチーム共有はありません。
- 集中時間の通知はアプリ内表示です。Windowsの通知バナーには未対応です。
- JSONバックアップは書き出しに対応しています。復元用の取り込み画面は未実装です。

# Orbit Organizer ✦

`dev-pre` のダウンロード整理アプリです。バージョン3.0では、選択プレビュー・整理履歴・設定画面を追加し、移動と復旧の安全性を強化しました。Windows / Node.js 22以降で動作します。

散らかった `Downloads` を、安心して片づけるためのゼロ依存アプリです。ブラウザの管理画面とCLIの両方から使えます。

まず管理画面を開くには `npm.cmd run manage`。実ファイルを使わず試す場合は `npm.cmd run demo` を実行してください。デモは一時フォルダに専用のサンプルを作成し、実際のDownloadsやDocumentsには触れません。デモの保存場所は起動時に表示され、終了後もサンプルは残ります。

ただ移動するのではなく、**先に全行程を見せる**、**作業中らしいファイルには触れない**、**実行後も一括で戻せる**ことを大切にしています。Node.js だけで動き、ファイル名の衝突時にも既存ファイルを上書きしません。

標準設定では「文書」「画像」「PDF」「インストーラー」「アプリ」などの整理先を `Documents` 直下に作ります。アプリの状態とUndo履歴は `%LOCALAPPDATA%\\Orbit Organizer` に分離するため、Documents に管理用フォルダを増やしません。

デスクトップの「ダウンロード配下整理ツール」をダブルクリックすると、プレビューと確認画面が開きます。コマンドを入力する必要はありません。

## 割り振り管理アプリ

デスクトップの「割り振り管理アプリ」から、整理ルールと配置済みアイテムを画面で管理できます。ブラウザを画面として使いますが、サーバーは `127.0.0.1` のみに公開され、外部通信は行いません。起動ごとにランダムなセッショントークンを発行します。

管理画面では次の操作ができます。

- 配置先カテゴリの追加、名称変更、削除
- カテゴリごとにDocuments以外や別ドライブの保存先を指定
- 新しい拡張子ルールの追加と削除
- `*Portable*` のようなフォルダ名ルールの追加と削除
- フォルダ名ルールの競合検知、原因表示、優先順位の変更
- Documentsにすでにあるフォルダを配置先として登録
- 配置済みファイルやフォルダの検索と複数選択
- 選択したアイテムを別カテゴリへ再割り振り
- 直近の再割り振りをUndo
- 移動元・移動先・容量を確認し、選択したアイテムだけを整理
- プレビューの検索、選択解除、CSV書き出し、保留理由の表示
- 直近50回の整理履歴と移動パスの確認、直近の未取消整理のUndo
- 待機時間、年・月別フォルダ、未分類、インストーラー許可、除外パターンの設定
- 設定のJSON書き出し、保存前の自動バックアップ
- 名前・種類による絞り込み、更新日・サイズ順の並び替え、Ctrl+Kで検索へ移動
- 最新状態への更新と、アクセス権・履歴・リンク・実行ロックの診断
- 狭い画面への対応、キーボードフォーカス表示、動きを減らす設定への対応

管理画面の「整理プレビュー」は10分間有効です。確認後に設定が変更された場合は実行を拒否し、プレビューの更新を求めます。選択情報はサーバー側の確認済み計画に照合します。実行中に更新されたファイルや、確認後に中身が変わったフォルダは保留します。

設定保存時は、直前の設定を `config.json.backup.json` に保存してから本体を置き換えます（別設定ファイルを使用した場合はその隣の `.backup.json`）。復元する場合はアプリを終了し、現在の設定も別名で保管したうえでバックアップを設定ファイルに戻してください。書き出した設定にはローカルパスが含まれます。

別の設定で管理画面を開くには `node manage.mjs --config my-config.json` を使えます。

カテゴリ名を変更すると、ルールだけでなく配置済みアイテムも一緒に移動します。中身のあるカテゴリは誤操作防止のため削除できません。先に画面上で中身を別カテゴリへ再割り振りしてください。同名ファイルがある場合は通常整理と同様に `(2)` を付け、既存ファイルを守ります。

新しく作るカテゴリの保存先は、既定では `Documents\\カテゴリ名` です。カテゴリを選択して「保存先を変更」を押すと、Pictures、Music、外付けドライブなど任意のフォルダへ変更できます。「参照...」からWindowsのフォルダ選択画面も利用できます。変更時には、そのカテゴリへ配置済みのアイテムも新しい場所へ移動します。

フォルダ名パターンが複数の配置先に一致する場合は、登録直後に競合画面を表示します。初期優先順位は、完全一致、固定文字が多い具体的なパターン、広いワイルドカードの順です。競合画面またはホームの「ルール競合センター」で優先する側を選べます。優先順位の変更は次回の整理から反映され、配置済みアイテムは自動移動しません。

コマンドから開く場合は次を使えます。

```powershell
npm.cmd run manage
```

## 安全設計

- Preview が標準動作です。明示的に `apply` するまで移動しません。
- シンボリックリンク、未知の種類、登録されていないフォルダには触れません。
- インストーラー形式は明示的に許可した場合だけ整理し、スクリプトなどその他の実行形式は引き続き拒否します。
- ポータブルアプリのフォルダは、`folderCategories` に登録された名前だけを移動します。
- `~$*`、`.crdownload`、`.part`、`.tmp` などOfficeロック・ダウンロード途中・一時ファイルを保留します。
- 更新後1分未満のファイルは、まだ書き込み中かもしれないため保留します。
- Preview 後にサイズや更新日時が変わったファイルは、Apply 時に移動しません。
- 同名ファイルがあれば `report (2).pdf` のような新しい名前を選び、上書きしません。
- ファイルは別ドライブへの移動にも対応し、コピー失敗時は元ファイルを残します。フォルダの別ドライブ移動は、再帰削除失敗から安全に復旧できないため中止します。フォルダが混在したバッチは途中まで移動している場合があるので、履歴を確認してUndoできます。
- 実行前にジャーナルを作り、各移動後にも履歴を保存します。履歴は `options.stateDirectory/history`（省略時は移動先の `.file-organizer/history`）、再割り振り履歴は同じ状態フォルダの `manager-history` に保存されます。履歴と設定は一時ファイルからの置き換えで保存し、中断時の復旧に備えます。
- 二重実行ロックと上書き不能な移動処理により、並行実行や確認後の競合から既存ファイルを守ります。
- Undo 時に元の名前がすでに使われていた場合も上書きせず、`(restored 2)` を付けます。
- 整理・再割り振り・設定変更・Undoは共通ロックで同時実行を防ぎます。異常終了後にロックが残った場合は診断で場所を確認し、該当プロセスが終了していることを確かめてからロックファイルだけを除去してください。
- Windows予約名、末尾ドット、状態フォルダへの分類、リンクを経由する移動先を拒否します。
- `.tar.gz` のような複合拡張子は長いルールを優先します。実行形式の保護は最後の拡張子にも適用します。

## 検証範囲と制約

`npm.cmd test` で従来機能と追加機能の回帰テストを実行します。HTTP経由でも認証、設定変更後のプレビュー拒否、選択整理、履歴、Undoを検証しています。テストは専用の一時フォルダを使います。

今回の環境ではブラウザ操作ツールのURL判定が停止したため、実ブラウザでの目視検証は未実施です。デモでウィンドウ幅の変更、ダイアログ、キーボード操作を確認できます。

年・月別フォルダの中身は、配置済み一覧ではフォルダ単位で扱います。自動の常時監視、重複ファイルの削除、クラウド同期、別ドライブへのフォルダ移動は実装していません。また、ファイル内容をハッシュ検証するバックアップ製品ではありません。同じサイズ・更新日時のまま行われる内容変更や、OS停止のあらゆるタイミングからの完全復旧は保証しません。

## ルールを変える

`config.json` で元フォルダ、移動先、カテゴリ、挙動を設定できます。パス内の `%USERPROFILE%` などのWindows環境変数は実行時に展開されます。

```json
{
  "source": "%USERPROFILE%\\Downloads",
  "destination": "%USERPROFILE%\\Documents",
  "categories": {
    "PDF": [".pdf"],
    "画像": [".jpg", ".png", ".webp"],
    "インストーラー": [".exe", ".msi", ".msix"]
  },
  "folderCategories": {
    "アプリ": ["clibor", "Office_Tool*"]
  },
  "categoryDestinations": {
    "画像": "%USERPROFILE%\\Pictures\\整理済み"
  },
  "options": {
    "minimumAgeMinutes": 1,
    "dateFolders": "none",
    "includeUnknown": false,
    "allowInstallerFiles": true,
    "unknownCategory": "Other",
    "maxPreviewItems": 40,
    "stateDirectory": "%LOCALAPPDATA%\\Orbit Organizer",
    "ignore": ["~$*", "*.crdownload", "*.part", "*.tmp"]
  }
}
```

`dateFolders` は `"none"`、`"year"`、`"month"` から選べます。`"month"` にすると `Images/2026-09/photo.jpg` のように整理します。`includeUnknown` を `true` にすると、未登録の種類も `unknownCategory` へ送れます。

危険な実行形式は、設定に書いても拒否されます。カテゴリ名はフォルダ1階層分だけを指定でき、移動先を元フォルダの内側にする設定も拒否されます。

## 設計思想

Orbit Organizer は「勝手に賢く片づける」より、「何をするか明快で、失敗しても戻れる」ことを選びます。定期実行や細かな分類に拡張しても、この透明性と可逆性は崩さない方針です。
